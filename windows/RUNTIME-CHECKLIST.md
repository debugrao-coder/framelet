# Windows runtime acceptance — PENDING

No Windows desktop is available in the current macOS build host. A successful cross-build is not Windows functional or performance evidence. Do not mark this checklist complete without the listed observations. Test on a synthetic desktop, not personal screens.

## Build and identity
- Run `./build.ps1 -Architecture x64 -Package` in PowerShell with .NET 8 SDK, Rust MSVC, C++ Build Tools and Windows SDK installed; use `rustup target add x86_64-pc-windows-msvc` when necessary.
- For ARM64 use `-Architecture arm64` and `aarch64-pc-windows-msvc`; ARM64 C++ cross-build components are required. Both architectures' real-device acceptance remains pending. The x64 GNU and ARM64 GNU/LLVM C ABI DLLs have been cross-built on Mac into their respective publish directories, with architecture/export/import validation, but neither has been loaded by Windows.
- Package is unsigned unless an existing certificate thumbprint is provided. Signing subject must match `CN=Framelet Local Development`. The script does not create/trust certificates or install the package. A local developer can explicitly choose and approve that trust step. No secret/signing key belongs in this repository.
- Start installed app from Start Menu to retain MSIX identity. Portable EXE intentionally explains that OCR needs package identity, rather than pretending to work.
- Run `./acceptance.ps1`; inspect self-test GIF with two frames and expected delays. This only checks synthetic encoding/join/ABI, not a real capture.

## Real product paths
1. Prepare an innocuous text editor with `Framelet 2026 中文识别 ABC 123.45` and a synthetic scrolling page. Disable private notifications before capture.
2. **Region:** click 截图 and drag a region. Verify bounds, dimensions, no picker pixels, image clipboard paste and PNG export. Repeat at 100/150/200% display scale; dual-monitor negative origins; crossing monitors; Escape cancellation. Expected selection is physical pixels. Mixed-DPI overlay alignment remains particularly important to validate.
3. **Hotkeys:** defaults Ctrl+Shift+2/3/4/5 start screenshot/scroll/GIF/OCR. Check current bindings in the launcher and use 快捷键设置 to change or disable them. Bind a requested combination in another program and confirm only the conflicted startup action is disabled with an explicit warning. Close Framelet and verify all owned shortcuts are released.
4. **Editor:** draw arrows, rectangles, text, opaque redaction; undo and export; verify output at 100% that redacted source pixels are not recoverable in the PNG. OCR should read the flattened edited image, not the covered original. Clipboard and save errors must stay visible.
5. **Scroll:** capture only the scrollable content, scroll downward less than half a frame, append. Confirm no missing/duplicated lines and exact output height. Repeat unchanged, animation, fixed header AND fixed footer, too-large jump; uncertain joins must not silently append. Complete must preserve all successful segments; miniature preview must match output, and 撤回一段 must restore the previous joined image. Check allocation cap error keeps the previous image AND its existing undo snapshot. All overlapping pixels are validated, including edges; changed edges must be rejected even if core estimates a positive translation. Upward scroll is not supported.
6. **GIF:** choose ≤2,073,600 pixels, move launcher out of region during countdown, record changing synthetic content, then stop. Open GIF in Edge: verify motion, palette, frame delays, loop, exact crop, no transparent corruption. Test stop during countdown, stop mid-record, automatic 60-second stop, full disk/write denial. Existing file is replaced only after successful temporary GIF completion and Save dialog overwrite confirmation. If final rename fails, verify the complete `.partial` GIF remains recoverable and its exact path is shown.
7. **OCR:** install suitable system Chinese/English OCR packs, launch signed installed MSIX. Compare results for both languages with reference text, linebreaks, punctuation, numbers. Verify missing-language, too-large image and missing-package cases explain the issue. Do not label approximate output exact.
8. Close with unsaved annotation, active capture/scroll processing and active recording. Verify explicit warning/stop path; no lost GIF or stale `.partial` files after normal errors/cancellation.

## Performance evidence (do not fill from estimates)
Record OS/build, hardware, driver, DPI, resolution, app version, cold/warm status and 30 runs for latency. Capture P50/P95, peak process working set, sustained CPU, GIF wall time and effective frames/sec. Profile WGC device/session startup, whole-monitor SoftwareBitmap CPU readback, region crop, explicit GDI fallback and WIC GIF quantization separately. Current source uses a persistent WGC/D3D11 session first with an explicit unsupported/cross-monitor GDI fallback. Whole-monitor readback means small-region WGC may be slower than GDI: this has not been measured. No hardware video encoding is implemented and the target 10fps is not claimed as achieved. Long screenshot holds bounded full raster images, not a tiled image store. The initial ≤150ms hot capture, ≤120MB idle, OCR ≤1s goals are UNVERIFIED.

MP4/hardware encoding, audio, recorder pause/resume, automatic scrolling and general-purpose zoom are NOT IMPLEMENTED in this Windows milestone. Do not advertise them as finished.

## WGC-specific acceptance (all PENDING)
- Confirm a single-monitor screenshot, GIF and manual scrolling report WGC/D3D11; inspect native device/session lifetime with Windows diagnostics to verify one session spans an entire recording and all handles/GPU memory return after stopping.
- Confirm still/scroll captures hide the launcher; GIF's WDA_EXCLUDEFROMCAPTURE request must actually exclude the owned launcher on the device. If exclusion fails, the app must explicitly instruct moving it outside the region. No other application's window affinity is changed.
- For cross-monitor region, confirm explicit GDI fallback text. For unsupported WGC/D3D, verify the same. For E_ACCESSDENIED/policy refusal, timeout, cancellation or device loss, verify failure without switching capture APIs or requesting permissions.
- Record static content, then update it; verify stale frames do not accumulate while CPU encoding is slower than the display. Manual scrolling after a long pause must use the latest frame. Test unplug/resize/rotation while recording: stop clearly rather than using wrong coordinates.
- Stop during first-frame waiting, CPU readback and encoding. A readback cancellation after previous frames must finalize existing GIF frames. A cleanup failure must not discard a fully encoded output. Verify visible Windows capture border is never disabled.
- Measure peak memory at 1080p/4K and mixed-DPI setups; whole-monitor readback and two GPU surfaces must be accounted for even for a tiny selected region. Compare against GDI rather than assuming WGC is faster.

## PNG save acceptance (Windows filesystem/WIC/UI all PENDING)
- Run `dotnet run --project tests/GifMuxTests.csproj -c Release` on Windows using a synthetic temporary directory. The Mac result is not proof of NTFS, removable volumes or network filesystem behavior. Verify atomic replace is supported or fails clearly without an unsafe fallback.
- Export a synthetic annotated/redacted image as a new PNG, then overwrite a synthetic existing PNG; reopen and compare exact dimensions/pixels. Verify save completion appears only after encoding, flush, close and commit.
- Test write denial, locked destination and full-disk conditions using disposable fixtures only. Existing target bytes must remain intact on failures; staging must disappear, or an explicit cleanup-error path must be shown. Never test faults against an original user file.
- During a large PNG export repeatedly invoke Ctrl+S, Ctrl+Z, copy, OCR and close (including launcher shutdown). Only one save should run, no canvas mutation should enter its frozen snapshot, close must be rejected until completion, and failure must retain dirty marks. Canceling the Save dialog restores normal interaction. Saving during an active drag/OCR should not start another operation.
- Confirm background WIC encoder accepts the frozen snapshot without Dispatcher/thread-affinity exceptions; save errors remain visible and no success label is shown after failure. Retest responsiveness and memory on large bounded captures. Abrupt process termination/power-loss durability is not guaranteed by these tests.

## OCR text protection (Windows runtime PENDING)
- Use a synthetic text image: recognize, manually correct text, request recognition again. Default action must cancel replacement; choosing No preserves every byte, choosing Yes permits replacement only if there are no newer edits.
- Type during recognition, including edit then revert. The late result must not overwrite the text. Missing language/package, blank result and an injected service failure must preserve existing text and its close protection. Progress belongs in status, never in the editable text area.
- Copy a partial selection, then close: unacknowledged text still warns. Successful full Copy Text or all-selected Ctrl+C acknowledges only that exact full string; clipboard failure must not. Edit after copy: warning returns. Saving a PNG must not acknowledge text. Native context-menu copy intentionally remains conservatively unacknowledged.
- Close during recognition: No keeps the editor, Yes requests cancellation and invalidates callbacks. Simulate a >30-second worker: the UI stops waiting, text remains, a second OCR cannot start until the first native worker actually exits, and late success/failure cannot modify a closed UI. Measure actual OS cancellation and bitmap lifetime separately; do not treat host Task tests as Windows cancellation evidence.
- Exercise simultaneous save/close/OCR, full-text keyboard copy and Chinese IME input; verify existing PNG/annotation protections remain intact. Both local self-contained bundles were refreshed after the OCR source changes; they still require this runtime acceptance.
